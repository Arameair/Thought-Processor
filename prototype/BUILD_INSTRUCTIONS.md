# Build instructions — prepared, not yet authorized
Human-directed, AI-assisted. Scope: a real local Thought Processor and its Identity-approved operational relationship with one selected Engine.

## Authority and branch rules
Begin implementation only after explicit owner assignment. Inspect the then-current Alpha and record its SHA; branch a fresh experiment from it, not from this documentation branch. No Alpha/Stable/Main changes or promotions.
This assignment owns Processor code only. Identity/Engine/launcher changes need separately assigned integration work.
Use the smallest stack consistent with actual repositories. Target one explicitly recorded owner-test OS first; do not claim Windows/WSL/Debian equivalence from a single-host test.

## Revised gates
### Gate 0: actual contracts before privileged code
Inspect actual code and runbooks. Produce a compatibility ledger with exact revisions, tested endpoints, authentication, fields, capabilities and blockers.
Define the consumer requirements for a real Identity start/attach decision; agree the wire contract with its owning project before integration.
If the producer is absent, return an exact dependency request. Do not create an always-allow authority, reuse an ingestion grant, or mark a manifest as Identity approval.

The decision contract must cover authenticated actor/Processor and installation, selected entity/session where applicable, intended action, expected target service/build-manifest binding, validity/freshness, decision identity and integrity/authenticity. Specify replay, concurrent-use, expiration, revocation, timeouts, key trust and unavailable behavior. These are requirements, not invented field names/endpoints.
Start, operational attach, stop and observation ingestion have separately defined scopes. The runner/control boundary validates approval; a frontend enabled button is not enforcement. Define the approved attach/read/control boundary with Engine's real supported authentication. If that boundary cannot be enforced, integration is BLOCKED.

### Gate 1: useful diagnostic shell
Independently runnable local Processor; honest self status, missing prerequisites and reconnect/setup route.
No required Identity/Engine/GitHub for rendering setup/repair. No normal operational READY without verified product prerequisites.
No fabricated user entities, feature cards, metrics, trust or permissions.
Before approval, discovery is limited to inspecting an explicitly configured same-host candidate or recorded launcher metadata: no scan, credential exchange, operational session, privileged diagnostics, original-app access or control request. Label candidate response fields as untrusted claims. If the endpoint cannot be safely classified as public read-only metadata, do not call it.
Show denied, unavailable, unsupported and unknown distinctly. Connection approval controls remain blocked if the real producer contract is missing.

### Gate 2: Identity-approved start/attach
Only after actual Identity and enforcement dependencies are available and verified.
Use one bounded runner for selected approved executables, not arbitrary shell commands. Processor asks; runner enforces and owns lifecycle. If shared runner is not ready, report BLOCKED, not a second unauthenticated manager.
Approved manifest binds executable path/digest, product/protocol, pinned source provenance, isolated data root, working directory, allowed arguments and supported local endpoint.
Attach-only approval cannot spawn; start-only approval cannot silently control an existing instance. A combined ensure action needs explicit coverage for its possible branches.
Verify approval at execution, not merely when the screen loaded. Repeated/concurrent requests must be idempotent; do not replay approval for an unrelated/new launch.
Separate process provenance from service authentication. Wrong product/build/instance/authority must not be accepted. A port or claimed SHA is not authentication.
Do not send observations or trigger inference during launch, attach or health checks.

### Gate 3: operations, recovery and evidence
Display genuine request → decision → runner result → service observation with correlated IDs and timestamps, without claiming atomic success across services.
Show one useful next action, real original interface access only when permitted, bounded logs/metrics and allowlisted Copy Context.
Mark unavailable diagnostic capabilities instead of adding cosmetic controls.
Preserve started-by-session versus external ownership across Processor restart using protected records plus live process identity verification. Bare PIDs are insufficient. If ownership is uncertain, do not kill or claim ownership; diagnose and reconcile without starting a duplicate.
Stop session-owned Engine: graceful stop, bounded wait, terminate only verified owned descendants if needed under an explicitly defined cleanup policy; record failure and retain data. Stop is separately authorized/control-policy defined. Any narrow cleanup of children from failed startup must be explicitly covered in the approved runner contract. No blanket port/name kills.
Browser close does not stop backend or Engine. Runner lifetime and restart behavior must be explicit; do not claim backend-crash survival if runner is a child that exits with it.

Protect loopback controls with an authenticated local operator session, protected bootstrap, trusted Host/Origin validation and anti-CSRF protection as appropriate to the chosen transport. Define CORS and reject untrusted origins/hosts; no state changes via GET. Test these properties. Do not expose an arbitrary URL proxy/command runner.
Expose diagnostics by capability/permission; unknown authorization does not permit private logs or controls.
