### A quiet computer, and an idea

Maya is at her desk. She has been playing a game for years. She wants a companion that can go along for the journey, notice what happens, and gradually offer something more useful than a chat box that forgets everything between questions.

She doesn't want to rent a fictional personality from a developer. She wants to **own a starting system**, choose its features, and decide what they are allowed to see.

She installs and opens **Identity** for the first time.

The welcome screen does **not** claim that services are connected, permissions have been granted, or any processing has occurred. It reports only facts the software can genuinely verify, and otherwise says **Not connected**, **Not checked** or **Unknown**.

> **Welcome. Let's establish your version.**
>
> This creates a version of the starting project in **your GitHub repository**, linked to its original creator. You'll choose which additional features to connect afterward.
>
> GitHub: **Not connected**  
> Your repository: **Not created**  
> Local installation: **Setup in progress**
>
> **[Connect GitHub]** · **[Recover an existing installation]**

Maya notices that she can inspect what she is about to create before granting access. If she's returning with an existing installation she can take the recovery path. There is no "Skip GitHub and pretend ready" button.

She wants to know a simple thing: *what do I own when I finish?*

The next screen answers that question before doing anything to her account.

### Behind the screen

Identity is permitted to initialize only the local information needed to guide setup and recovery. A functioning feature ecosystem has **not** been authenticated or started. Nothing has been created in GitHub, nothing from the publisher's feature repositories has been unlocked, and nothing has been sent to an AI model.

This is intentionally different from an earlier local-only Identity story: the current owner direction makes a verified user GitHub connection part of the **normal full product opening**, not an optional extra. The low-level Identity process may still start to help with setup/repair.

### What must be true if we ever build this

- The UI distinguishes **software open** from **product ready**.
- The user has not inadvertently consented to create a repository or reveal data.
- Recovery preserves the original IDs and avoids creating a second version.
- Missing GitHub is an understandable step, not an error that erases local data.

**Blueprint question:** How can the opening screen show only verified account/setup state, allow recovery, and avoid creating anything before explicit consent? See [Trust and evidence](TRUST-AND-EVIDENCE.md).
