# Note: grant path required before core-path prototype schematic

*(outside-user observation — 2026-10-24)*

Both Identity and Thought Processor are required for the core brain path. Neither is ready for a prototype schematic of that path until a concrete, enforced grant exists that the Thought-engine actually checks at observation ingest time and that Processor can display honestly.

## What is still missing

- Identity does not yet issue a grant the engine verifies.
- The experimental Thought-engine currently holds its own local “Thought Processing ON/OFF” flag.
- Processor remains documentation-only. It cannot show real PERMISSION DENIED / grant-verified states until the engine performs the check.
- Issue #2 (canonical engine) is still open. A schematic that assumes one cognitive store is premature while two prototypes exist.
- The Identity–Experience hypothesis is unproven. Processor’s value as a control point does not depend on the hypothesis being true; it depends on showing the actual pipeline and the actual permission result.

## What would make a schematic useful

1. Identity writes or serves a short-lived, locally verifiable grant for an identity.
2. Thought-engine, on incoming observation, checks that grant and rejects (does not queue) when it is missing or revoked.
3. Processor connects only after the engine reports both live status and the real grant outcome (or the honest label “grant held locally — Identity not connected”).
4. Toggling the grant off is visible in Processor and stops new observations without requiring an engine restart.
5. Explicit list of what is deferred (background registration service, full multi-feature catalog, OAuth, automatic feeds).

Until those five points are decided and the first three are demonstrable, any schematic of the core path will be illustrating options rather than a buildable design.
